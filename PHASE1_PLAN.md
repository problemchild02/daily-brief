`id`, `section`, `headline`, `hook`, `summary`, `contextNote`, `source`, `sourceUrl`, `dateLabel`, `tags[]`, `priority`

## (c) Phase 1 Execution Plan

Each task below is scoped to be its own PR. Tasks are ordered so each PR has a working deploy on GitHub Pages — no PR leaves the site broken.

The critical path is: **bootstrap → tokens → data shape → Masthead → Card → SectionDeck → App shell → SettingsSheet → meta.json → QA**.

---

### PR 1.0 — Bootstrap: Vite + React + TypeScript + Tailwind v4 + GitHub Pages deploy

**Goal:** Establish the build system. After this PR, `npm run dev` starts a local server and `npm run build` deploys correctly to GitHub Pages. The site does not need to look different yet — this PR can render "Daily Brief loading…" — as long as it deploys and existing `stories.json` / `sw.js` still work.

**Scope:**
- `npm init` and `package.json` with all dependencies from §2 (`motion`, `cmdk`, `@dnd-kit/*`, `react-loading-skeleton`, `lucide-react`, `react-virtuoso`, `date-fns`, `clsx`, `tailwind-merge`) and dev deps (`rss-parser`, `@anthropic-ai/sdk`).
- `vite.config.ts` with `base: '/daily-brief/'` for GitHub Pages.
- `tsconfig.json` (strict mode).
- Minimal `src/main.tsx` and `src/App.tsx` — renders `<h1>Daily Brief</h1>`.
- `index.html` at root (Vite entry point) importing `src/main.tsx`.
- Tailwind v4 wired into Vite (`@tailwindcss/vite` plugin).
- `.github/workflows/deploy.yml` — on push to `main`, runs `npm ci && npm run build`, then deploys `dist/` to GitHub Pages via `actions/deploy-pages`.
- `.gitignore` additions: `dist/`, `node_modules/`.

**Acceptance:** `https://problemchild02.github.io/daily-brief/` loads the new React shell. Existing workflow files still run unmodified.

**Goal:** The exact CSS variable names from §4 are live and Tailwind utility classes (`bg-canvas`, `text-ink`, `font-serif`, etc.) resolve to those variables.

**Acceptance:** `bg-canvas` renders `#FAF8F4`; `text-ink` renders `#1A1A1A`; `font-serif` loads Newsreader. Both light and dark values verified in dev tools.

### PR 1.2 — Data layer: story shape migration, `src/data/` structure, `sources.json`

**Goal:** The React app can load and type-check story data. Story objects gain `kicker`, `wordCount`, `publishedAt` (ISO string) so `Card.tsx` can render reading time and relative timestamps.

**Scope:**
- `src/data/sources.json` — extract the feed URL list from `fetch_stories.py` into a declarative JSON file (feed URL, display name, section, weight).
- `src/data/meta.json` — seed file with `{ "editionNumber": 1, "lastRefreshIST": "", "feedHealth": {} }`.
- TypeScript type definitions: `src/lib/types.ts` with `Story`, `Section`, `MetaJson`, `BriefingJson` interfaces.
- Update `fetch_stories.py` to emit `publishedAt` (ISO 8601) and `wordCount` (word count of `summary + contextNote`) per story. No `kicker` for RSS stories (optional field, defaults to `undefined`).
- Add word count computation to `process_papers.py` for parity.
- `src/hooks/useFeeds.ts` — fetches `/daily-brief/stories.json`, returns typed `{ sections, heroStoryId, editionDate }`.

**Acceptance:** `useFeeds` resolves with typed data; TypeScript reports 0 errors on story shape; `wordCount` present in next `stories.json` commit.

### PR 1.3 — Masthead + `useTheme` hook

**Goal:** The newspaper masthead (§6.1) renders at the top of every page with correct typography, sticky scroll behaviour, and a working theme toggle.

**Scope:**
- `src/hooks/useTheme.ts` — reads/writes `localStorage["daily-brief:theme"]`; applies `data-theme` attribute to `<html>`; respects `prefers-color-scheme` as default.
- `src/components/layout/Masthead.tsx` — renders wordmark in Newsreader 700, date line in Inter 13px, edition number from `meta.json`. Right-side icons: theme toggle, settings (gear), search (slash) — all 44×44 touch targets with `aria-label`.
- Sticky scroll behaviour: `position: sticky; top: 0` with reduced height after 200px scroll (using `IntersectionObserver` on a sentinel element; no `scroll` listener for performance).
- Google Fonts `<link>` tags for `Newsreader`, `Inter`, `JetBrains Mono` added to `index.html`.

**Acceptance:** Wordmark displays in Newsreader; date shows today's date in IST; edition number shows from `meta.json`; theme toggle persists across page reload; masthead sticks on scroll.

### PR 1.4 — `Card.tsx` + `lib/readingTime.ts` + `lib/categories.ts` + `lib/dateFormat.ts`

**Goal:** A single Card component handles standard, hero, and list variants with all the fields required by §6.2.

**Scope:**
- `src/lib/readingTime.ts` — `readingTime(wordCount: number): number` returns `Math.ceil(wordCount / 225)`.
- `src/lib/dateFormat.ts` — `relativeTime(iso: string): string` (e.g. "3h ago", "Yesterday"); `formatIST(iso: string): string` for display.
- `src/lib/categories.ts` — verbatim from §5, typed as `const`.
- `src/components/cards/Card.tsx` — implements standard, hero, list variants per §6.2 CardProps interface. Category kicker uses `var(--cat-${category})`. Bookmark button wired to `useBookmarks` stub.
- `src/components/cards/SkeletonCard.tsx` — uses `react-loading-skeleton` to render a plausible card-shaped skeleton (one line for kicker, two for headline, one for metadata).

**Acceptance:** `Card` renders correctly for a mock story at all three variants; `readingTime(450)` returns `2`; SkeletonCard displays without errors.

### PR 1.5 — `SectionDeck.tsx` + `SectionHeader.tsx`

**Goal:** Each content category renders as a labelled grid of cards with a header showing last-refresh time and feed health.

**Scope:**
- `src/components/sections/SectionHeader.tsx` — accepts `category`, `lastRefresh` (ISO string), `feedHealth` (`{ ok: number, total: number }`). Renders category label in category colour, `"Last fetched: <relative time> · X/Y sources OK"` in mono text. Shows a warning icon if any source failed.
- `src/components/sections/SectionDeck.tsx` — accepts `category` and `stories[]`. Renders `SectionHeader` + the `auto-fit minmax(320px, 1fr)` grid of `Card` components. If `stories` is empty, renders a short "Nothing new in this section" empty state. Accepts an `isLoading` prop to render `SkeletonCard` items instead.

**Acceptance:** `SectionDeck` renders for at least one live section; empty state displays when stories is `[]`; skeleton shows when `isLoading` is true.

### PR 1.6 — App shell wire-up: `App.tsx` composing Masthead + all SectionDecks

**Goal:** The live site renders all eight sections using `Card`, `SectionDeck`, and `Masthead` from real `stories.json` data. This is the first PR where the new React site visually replaces the old HTML/CSS/JS site.

**Scope:**
- `src/App.tsx` — composes `Masthead` + one `SectionDeck` per section (legal, business, reliance, retail, tech, world, sports, opinion) fed from `useFeeds`. Handles loading state with skeletons and error state with a message.
- `src/hooks/useBookmarks.ts` — CRUD over `localStorage["daily-brief:bookmarks"]`; exported as `{ bookmarks, toggle, isBookmarked }`.
- Wire `BookmarkButton` inside `Card` to `useBookmarks`.
- `src/components/layout/ScrollToTop.tsx` — renders a floating button that appears after 500px scroll; `onClick` calls `window.scrollTo({ top: 0, behaviour: 'smooth' })`.
- `styles.css` is kept for the service worker offline fallback; the React build supersedes it for live use.

**Acceptance:** Full front page renders with real stories; bookmarking persists across reload; no TypeScript errors; `npm run build` succeeds.

**Goal:** All settings (theme, density, home city, PAT, PDF upload) live in one slide-up sheet accessible from the gear icon in the Masthead. The standalone settings modal and PDF import modal are removed from `index.html`.

**Acceptance:** Gear icon opens sheet; theme/density changes apply immediately; PAT saved and "Run workflow now" dispatches correctly; PDF import flow still works end-to-end.

### PR 1.8 — Edition counter: `update-meta.mjs` + workflow integration

**Goal:** `meta.json` is written on every successful refresh run with an incrementing edition number, last-refresh timestamp, and per-feed health status.

**Scope:**
- `scripts/update-meta.mjs` — reads `src/data/meta.json`, increments `editionNumber`, writes `lastRefreshIST` as `Intl.DateTimeFormat('en-IN', { timeZone: 'Asia/Kolkata', ... })` output, copies `feedHealth` from `fetch_stories.py` output (or reads a sidecar `feed-health.json` written by the Python script).
- Update `fetch_stories.py` to emit `feed-health.json` with `{ ok, total, byFeed: { feedName: "ok"|"error" } }` so `update-meta.mjs` can read it without parsing Python stdout.
- Update `.github/workflows/daily-update.yml` to run `node scripts/update-meta.mjs` after the Python fetch step and `git add src/data/meta.json` before the commit.
- `src/data/sources.json` consulted by `update-meta.mjs` to know the total expected feed count.

**Acceptance:** After next workflow run, `meta.json` has `editionNumber > 0` and `lastRefreshIST` non-empty; Masthead renders the edition number; SectionHeader shows feed health counts.
